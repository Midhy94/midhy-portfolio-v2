5A. MANDATORY HUMAN-CRAFTED DESIGN RULES — NO GENERIC AI WEBSITE

This section is a core design requirement, not optional polish. Apply it
to every public page and, where appropriate, the CMS. The goal is a
website that feels individually art-directed and carefully implemented
by an experienced designer and frontend engineer—not a generic
AI-generated template.

A. Design from content, not from a template

-   Make visual decisions based on the actual content, project imagery,
    narrative, and user goals.
-   Give every section a clear purpose. Remove sections that exist only
    to make the page longer.
-   Do not repeat the same section recipe throughout the site.
-   Avoid the predictable pattern of eyebrow label + oversized heading +
    short paragraph + three cards.
-   Do not force every piece of content into a card.
-   Do not use a fixed number of cards, columns, or feature items simply
    because it is a common template pattern.
-   Vary composition intentionally while retaining a coherent underlying
    design system.
-   Use asymmetry, offset alignment, different image proportions, and
    changes in content density only when they improve hierarchy or
    storytelling.
-   Let some sections be quiet and restrained. Reserve visual emphasis
    for the content that deserves it.
-   Every decorative element must have a clear visual or functional
    purpose. If it adds no meaning, remove it.

B. Explicit anti-template rules

Avoid these patterns unless there is a clear, content-specific reason to
use them:

-   Generic gradient blobs, neon glows, glassmorphism, floating circles,
    and random abstract decorations.
-   Repeated rounded rectangles and excessive pill-shaped UI.
-   The same three-column grid repeated across multiple sections.
-   Identical project cards with only the title and image changed.
-   Excessive badges, eyebrow labels, tiny uppercase captions, and icon
    lists.
-   Oversized headings in every section.
-   Unnecessary counters, animated statistics, progress bars, and skill
    percentages.
-   Fake code editors, terminal windows, AI dashboards, or futuristic AI
    imagery used only to signal technical expertise.
-   Generic slogans such as “Let’s build something amazing” or “Crafting
    digital experiences” unless rewritten into a specific, authentic
    statement.
-   Stock imagery presented as personal work.
-   Fake client logos, testimonials, project metrics, or project
    screenshots.
-   Decorative cursor effects, custom cursors, excessive parallax, and
    animations that delay content.
-   Shadows, borders, and rounded corners applied to every element by
    default.

Do not simply replace one trend with another. Restraint and context
matter more than novelty.

C. Typography must feel art-directed

-   Treat typography as a primary design material, not just a default
    heading scale.
-   Establish a clear relationship between display typography, section
    headings, body text, captions, and metadata.
-   Use intentional line breaks and control text measure for comfortable
    reading.
-   Avoid oversized headings when a smaller, more precise typographic
    treatment would communicate better.
-   Vary weight, scale, and alignment to create hierarchy rather than
    making every heading bold and large.
-   Use serif/sans-serif contrast only when supported by DESIGN.md and
    the overall identity.
-   Avoid excessive letter spacing and all-caps labels.
-   Use responsive typography that remains composed across mobile,
    tablet, and desktop.
-   Verify font loading and provide suitable fallbacks.
-   Do not use typography as a substitute for meaningful content.

D. Layout, spacing, and visual rhythm

-   Use a consistent underlying grid and spacing system, but do not make
    every section identical.
-   Give text and imagery room to breathe without creating large,
    purposeless empty areas.
-   Avoid both cramped layouts and excessive whitespace that makes the
    page feel unfinished.
-   Establish hierarchy through alignment, scale, proportion, contrast,
    and grouping.
-   Use full-bleed imagery only when the image and narrative justify it.
-   Use narrow reading columns for long-form text and wider layouts for
    visual work.
-   Vary the rhythm between dense information, visual showcases, and
    quiet editorial moments.
-   Align edges and baselines deliberately. Small inconsistencies should
    not be left as accidental visual noise.
-   Do not use arbitrary fixed heights that cause clipping or awkward
    blank space.
-   Review the actual rendered page at multiple viewport sizes, not just
    the source code or a single screenshot.

E. Project imagery must lead the portfolio

-   Treat the actual design work as the main visual asset.
-   Prefer real project screenshots, interface details, prototypes, and
    images supplied in the project.
-   Give projects individual compositions where their content warrants
    it; do not force every project into an identical thumbnail card.
-   Use image crops, scale, and aspect ratios deliberately.
-   Maintain visual consistency without making all project presentations
    interchangeable.
-   Never present generated mockups, stock photos, or invented UI as
    genuine client work.
-   If project assets or details are missing, use a restrained
    placeholder and keep the project unpublished until accurate content
    is available.
-   Do not invent project stories to fill empty layouts.
-   Respect client confidentiality and avoid exposing sensitive product
    information.

F. Authentic, specific copy

-   Write like a thoughtful professional, not like a marketing template.
-   Prefer clear, specific sentences over vague claims such as “I
    transform ideas into impactful experiences.”
-   Use the resume as the source of truth for career facts, dates,
    achievements, skills, and qualifications.
-   Use only verified project information for case studies.
-   Do not invent personal interests, motivations, testimonials, client
    names, business results, or project responsibilities.
-   Avoid repeating the same professional summary in the hero, About
    page, and every project page.
-   Give each page a distinct communication goal.
-   Keep calls to action natural, concise, and relevant to the user’s
    next step.

G. Purposeful color and surfaces

-   Use the palette in DESIGN.md as the foundation.
-   Keep the required mixed light-and-dark visual rhythm, but do not
    alternate themes mechanically.
-   Use color to create hierarchy, contrast, and meaning—not to decorate
    empty space.
-   Do not introduce random accent colors, gradient backgrounds, or
    glowing effects.
-   Use borders, shadows, and radii selectively rather than applying
    them uniformly.
-   Check contrast and readability on every surface.
-   Ensure light and dark sections feel like parts of one identity, not
    separate templates stitched together.

H. Motion should be restrained and meaningful

-   Audit existing animation before adding new animation.
-   Use motion to explain state changes, guide attention, reveal
    imagery, or support narrative.
-   Do not animate every heading, card, image, and list item.
-   Avoid repeated stagger effects, long entrances, exaggerated easing,
    scroll hijacking, and decorative parallax.
-   Keep important content available immediately and ensure animations
    never block interaction.
-   Use transitions that feel natural and consistent.
-   Respect prefers-reduced-motion.
-   Test performance on mobile devices and use performant properties
    where possible.

I. Handcrafted frontend implementation

Implement the design through the existing Vue 3, TypeScript, Vite, and
SCSS stack.

-   Preserve working architecture, routes, CMS behavior, and Supabase
    security.
-   Build reusable components only where a genuine recurring pattern
    exists.
-   Do not create an over-generalized component system that makes unique
    page compositions difficult.
-   Keep design tokens centralized and component styles understandable.
-   Use semantic HTML, accessible controls, and clear component names.
-   Remove obsolete styles, dead code, and unused visual effects when
    safe.
-   Avoid brittle selectors, arbitrary magic numbers, excessive
    !important, and unnecessary dependencies.
-   Do not fake functionality with static UI or decorative controls.
-   Do not optimize only for a screenshot; ensure the implementation
    works across screen sizes and real content lengths.
-   Do not rewrite the application from scratch unless the current
    architecture genuinely blocks the required quality.

J. Mandatory visual review loop

After implementing the redesign:

1.  Run the application and inspect the rendered pages.
2.  Review the homepage, work listing, at least one case study, About,
    Contact, and key CMS screens.
3.  Inspect desktop, tablet, and mobile layouts.
4.  Identify repeated compositions, weak hierarchy, awkward line breaks,
    inconsistent spacing, empty placeholders, and unnecessary effects.
5.  Make a second refinement pass based on what is actually visible.
6.  Check console output, routes, interactions, and build status.
7.  Confirm that the redesign did not break CMS functionality,
    persistence, authentication, or security.

Do not declare the redesign complete after changing colors or editing
CSS without reviewing the actual result.

K. Human-craft acceptance test

Before marking the visual work complete, ask:

-   Does this look specific to Midhun and his actual work, or could it
    belong to any designer?
-   Are the layouts varied for a reason, rather than varied randomly?
-   Is every card, badge, icon, border, and animation necessary?
-   Is the typography composed with intention?
-   Do real project visuals take priority over decoration?
-   Does each section have a distinct purpose and rhythm?
-   Does the site remain visually coherent across light and dark
    surfaces?
-   Does the mobile layout feel intentionally designed rather than
    merely compressed?
-   Are all claims and project details accurate?
-   Has the running website been visually reviewed after implementation?

If the answer reveals generic or repetitive patterns, refine them before
completion.

Primary principle: do not imitate “human design” through imperfections
or random decoration. Achieve a human-crafted result through
specificity, restraint, strong hierarchy, authentic content, deliberate
composition, and careful implementation.
